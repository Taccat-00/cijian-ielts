# FSRS 与学习数据

## 调度

使用官方 `ts-fsrs 5.2.3`，模型 FSRS-6，21 个默认权重和 0.90 目标保持率。没有个人参数训练、优化器或外部调度服务。为衔接按天且按词去重的现有队列，使用库支持的 `enable_short_term:false`，不加入分钟级循环，也不覆盖返回的到期时间。

库的状态包括 due、last_review、stability、difficulty、elapsed_days、scheduled_days、learning_steps、reps、lapses 和 state；保存每次真实复习返回的完整 ReviewLog。库日期序列化为 ISO 8601 UTC，调用前恢复 Date。日期展示和每日任务继续使用原先保存的学习时区。

FSRS 决定记忆状态和到期时间，业务计划决定每日词条和进度：先分配到期复习，再补新词；当天计划冻结。同一单词当日只计一次完成，但独立练习中的再次作答仍是新的 FSRS 复习事件。

事件 ID 是 `(sessionId, questionIndex)`。持久层在评分和调度前拦截同题重复提交；先错后尝试改对不会把原 Again 改成 Good。显示释义、发音、笔记、收藏、切页和刷新不会生成复习事件。跳过仍按原规则进入错题本，但不创建调度日志。

## 旧记录

主键仍是 `cijian.ielts.v1`，根格式 `version:2`；FSRS 采用 `srs.algorithmVersion:2`，旧兼容卡片仍可保留版本 1。旧 v2 历史只有最近 20 条事件及摘要，无法可靠回放完整历史，因此升级时只添加根版本与配置，保留原日程、计划、学习身份和统计。下一次真实作答才用空记忆参数接收真实评分；不会将旧阶段当作难度或稳定性。

旧卡首次采用 FSRS 时缺少先前记忆参数，因此与完整历史初始化可能不同，但不会被当作未学新词重新占名额。原阶段保留在 `legacySchedule`，旧日志与摘要继续保留。

升级前先将原始主键字符串备份到 `cijian.ielts.backup.pre-fsrs.v2` 并读回核对，再单次写入新快照。旧 v1 沿用“备份并升级”入口，原始备份键为 `cijian.ielts.backup.v1`。不同备份、配额不足、损坏数据或存储冲突会停止升级；重复执行不会再建复习事件。只读页不执行持久迁移。

全部新 FSRS 日志保留。localStorage 配额不足时使用现有未保存/重试流程；校验成本会随历史增长，尚未验证多年大量记录的性能。

## 备份与恢复

代码仓库不是学习数据备份。浏览器开发者工具的 Application / Local Storage 可查看和复制主键及两个备份键的完整值；将其另存为本地文件。

恢复前先关闭其他学习页并独立备份当前值。在相同浏览器配置、协议、主机和端口下，打开不运行应用的同源静态页（例如 `/src/vendor/ts-fsrs-LICENSE.txt`），将确认过的原始 JSON 字符串写回主键，再返回应用刷新。不要清空整个存储，不要手工拼接 FSRS 卡片。

恢复升级前快照需配套使用能读取旧格式的代码；新版会再次安全升级它。恢复到历史备份会撤销备份之后的练习结果，因此始终先保存当前快照。当前没有跨设备同步或导入导出页面。

## 验证方式

`tests/fsrs-integration.test.mjs` 对照独立安装的官方 npm 包，检查首次评分、提前/逾期/同日复习、遗忘后学习的完整状态和日志，并覆盖迁移幂等、原始备份、失败恢复、只读、重复提交和每日队列。库分发文件与 MIT 许可证也进行逐字节核对。

项目现有测试还覆盖计时、题型、错题、生词、笔记、章节设置、跨天及存储冲突。没有私有完整词表时，对其的可选解析测试会标记跳过；其余测试使用自编样例或合成数据。
